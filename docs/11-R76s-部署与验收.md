# R76s 部署、验收与回滚

## 当前版本

这是第三代容器化的离线候选版本，不是已完成真机验收的发行版。程序入口为 `python -m spk_platform.cli`，不是旧的 `src/install.sh`。

已实现：音乐管理页面、管理员会话与 CSRF、配置 revision/回滚、加密密钥版本、缓存/本地/上传音乐、队列/换歌/停止/重播、闹钟、设备 v2 协议、Chat Completions/Responses、模型发现与独立能力探测、Azure 连续 ASR/文件与可选流式 TTS、受控 MCP 搜索接入、诊断/普通备份。

2026-11-03 本机 Linux x86_64 的 Python 3.11.18 和 3.12.3 各通过 113 项离线回归。真实无声 WAV/MP3 转码、HTTP/Range、SDK SSE 夹具、连续会话事件、MCP stdio 握手/发现和模拟设备闭环已验证；桌面 1440px/手机 390px 页面验证无横向溢出，图片和图标正常加载。没有访问音箱或调用付费 API。

## 设备安全审计边界

本次按 [危险操作清单](07-危险操作清单.md) 核对新增平台、容器入口、设备 v2 代理和旧模块改动：没有新增刷写 NAND/MTD、FEL/OTA 升级、改引导程序或分区、写 DSP/EQ/MCU 串口、写进程内存、独占声卡或重启原厂服务的执行路径。历史维护和探测脚本仍保留，但不是本版入口，也不应作为本版部署步骤运行。

- `start.sh` 只构建或显式发布镜像，不推送设备脚本、不启动音箱服务。缺少跨架构能力时只提示 QEMU 安装方式，不执行特权安装；不要在承担主路由的 R76s 上未经评估运行提示中的宿主级命令。
- 运行容器无特权、无宿主 PID/设备/Docker socket 共享。网易云兼容取流只在 resolver 内解析地址、清理其进程，不调用旧 ADB 响铃路径。
- v2 只调用既有 `play601.sh` 的播放/停止，以及既有 Headphone/Phoneout 静音开关；不设置 DAC 音量，不新增原生暂停/seek 命令。续播在服务器上截取音频，45 秒保护尾巴仍保留。
- v2 单实例锁原子记录 PID，并核对进程命令行，避免空 PID 或 PID 复用导致永久锁死。静音配置只在内容改变时同目录原子替换，失败保留旧配置；设备运行状态写入 `/tmp`。

这里的结论是“未发现新增刷机致砖路径”，不是“所有操作零风险”或“已完成真机验收”。静音开关会影响可听性，停止/切歌会打断播放，手工部署仍会写应用文件；这些不等于裸 NAND 刷写，但必须保留回滚条件。在真实音箱上仍须有人在场、使用当前保守音量并按维护窗口验收，不能据离线测试承诺绝不会变哑、重启或故障。

## 部署前门槛

1. 在 R76s 核对架构、可用内存/磁盘、系统时间、Docker Engine 和 Compose。需要 Compose 2.24 或更新版本；先确认它是否承担家庭主路由，保留原有服务资源余量。
2. 本机没有 Docker daemon，因此只验证过 Compose 配置，未验证镜像构建、非 root 卷初始化、bridge 收包来源 IP 或真实 ARM64 wheel/动态库。不要把 manifest 包含 ARM64 当作已通过 ARM64 运行验收。
3. 网易云 CLI 固定为 `@music163/ncm-cli@0.1.7`，不绕过账号播放权限。首次写入配置命令已用隔离假数据验证；真实登录、搜索、歌单和取流仍需账号验收。
4. `npm audit` 修补后仍有 4 项 high 风险，涉及官方 CLI 的 `build`/`timespan` 旧链和 Zod；不能作为“无漏洞版本”上线。resolver 无 LAN 端口、独立账号卷、关闭安装脚本，但这些隔离不能替代依赖修复。对外或长期使用前需审阅可达性、批准例外，或选择维护中的合法 provider。
5. 本地 KWS 模型、原音箱采音注入库、音乐账号和家庭记忆不随仓库提供。缺少 KWS 模型时使用设备原生唤醒入口，不启动完整本地 ASR 后备。
6. 按 [危险操作清单](07-危险操作清单.md) 预约真机测试窗口。默认不刷固件、不改 DSP/EQ、不接管声卡，也不启用 `adb tcpip 5555`。

## 容器启动

所有命令在仓库根执行。首次只通过可信本机连接配置；不要将云 Key 写入 Compose 环境文件。

```sh
docker compose --env-file config/compose.env.example --profile voice --profile search config --quiet
./start.sh build   # 或 docker compose --env-file config/compose.env.example build
docker compose --env-file config/compose.env.example up -d
docker compose --env-file config/compose.env.example ps
```

所有服务共用同一个 `runtime` 镜像（`SPK_IMAGE`，默认 `neteast-spk-server:latest`），由 `command` 决定运行 control/media/resolver/voice/mcp。使用 Docker Hub 私有镜像时，在自己的环境文件设置 `SPK_IMAGE=docker.io/pczhao1210/neteast-spk-server:latest`，在可信终端 `docker login` 后执行 `docker compose --env-file <文件> pull` 和 `docker compose --env-file <文件> up -d --no-build`；Docker 会自动选择 R76s 的 ARM64 镜像。

默认只绑定 `127.0.0.1`；浏览器入口为 `http://127.0.0.1:8080`。远程工作站使用 SSH 端口转发。Docker 转发可能使请求来源看起来不是 loopback，此时通过可信终端取得初始化令牌，在首次初始化页面输入，不发到聊天、截图或日志：

```sh
docker compose exec -T control python -m spk_platform.cli export-bootstrap-token
```

正式 LAN 使用时，在自己的 Compose 环境文件设置 `SPK_LAN_BIND` 为 R76s 的实际 LAN IP，设置 `SPK_PUBLIC_URL` 为反向代理提供的 HTTPS origin；Key 输入必须经过 HTTPS。同源、Origin 和 cookie secure 设置依赖该值，不要伪造为 HTTPS 后继续用 HTTP 浏览器访问。现有 HTTPS 反向代理需关闭 SSE 缓冲，并给样本探测/媒体上传设置合理的 body/timeout 上限。

修改宿主端口、卷和服务内部 URL 需要重建/重启，不是页面热更新字段。公开 TCP 8080、8898、8899 仅用于管理、设备轮询和带票据媒体；旧 8896 创建接口不在 Compose 中公开。麦克风为 UDP 9998；原生唤醒脚本实际使用 TCP 9997，新 voice 同时兼容 TCP/UDP 9997。

先运行目标机镜像预检，不发云请求、不访问设备：

```sh
docker compose run --rm control preflight --strict
docker compose --profile voice run --rm --no-deps voice preflight --voice --strict
```

通过后才启用语音/搜索 profile：

```sh
docker compose --profile voice --profile search up -d --build
```

## 页面配置

- 音乐为默认页。缓存/本地音乐和停止不经过 LLM/Azure；搜索/歌单/取流需要 resolver 与实际账号。停止/重播是真实控制，暂停、seek 和有效音乐软件音量未验证，因此不展示这些能力。
- 设置页保存 draft，不影响当前应用 revision；显式应用后新任务取不可变设置及密钥版本。密钥更新保存为草稿版本，不能将掩码当作新 Key；清空需单独确认。失败保留旧应用版本。
- 设备页填写实际 IP、严格 CIDR 和音箱可达的媒体 URL，例如 `http://<R76s-LAN-IP>:8899`。不要填 localhost、Compose 服务名或 `0.0.0.0`。bridge 模式的来源 IP 必须实机确认。
- LLM 填 API base，不在代码中自动追加 `/v1`。模型目录、文本、工具和流式是四项独立测试；没有模型列表时可以手填。Azure OpenAI v1 的 model 是部署名，Speech Key 与 OpenAI Key 分开。
- Azure 填实际 Region 或 Speech Endpoint。样本 ASR 探测只接受已获授权的、最长 10 秒、16kHz/mono/PCM16 WAV；计费测试必须显式确认。完整文件 TTS 是默认，可选流式需另做固件首尾/取消验收。
- MCP 默认关闭。推荐先选择受控 `brave-search` stdio 模板，密钥引用填写对应后端 Key；传输鉴权选 `none`，Brave API Key 只进入子进程的最小环境。远程服务支持 Streamable HTTP 与 Bearer/API Key header，OAuth 和旧 SSE 不静默兼容。
- 先发现工具，逐项勾选 schema/description hash 授权，设置默认搜索工具 `search` 和查询参数 `query`，再保存/应用；模型页明确填写允许的 MCP 服务 ID。目录变化需要重新审阅，不自动授权。两种 LLM 协议共用客户端工具桥接。
- 搜索策略为关闭/自动/仅明确联网。真实搜索/LLM 闭环需确认费用和账号；无结果或失败不宣称“已联网”。敏感查询默认不缓存。

## 管理员密码重置/修改

忘记管理员密码时，使用可信主机终端或 control 容器的交互终端，不需要旧密码：

```sh
docker compose exec control python -m spk_platform.cli reset-admin-password
docker compose restart control
```

命令会隐藏输入并要求确认两次，新密码需 12–256 个字符。不要加 `-T`，不要把密码放在命令参数、环境变量、管道或聊天中；不能隐藏输入、确认不一致或取消时不修改任何认证信息。

该命令也可用于正常修改密码，仅更新密码哈希和会话版本，不删除配置、云 Key、音乐账号、缓存或闹钟。旧登录会话失效，已打开的状态流在下次校验时关闭；重启 control 可确保旧运行进程和持续连接也已清理。已提交的设备任务不是密码记录，重启可能中断当前会话，应在合适时段操作。

本机开发预览需要指定它实际使用的数据与密钥目录，例如：

```sh
PYTHONPATH=src .venv/bin/python -m spk_platform.cli reset-admin-password \
  --state-dir .cache/ready-state --key-dir .cache/browser-keys
```

此时重启使用该目录的本机 control 进程即可。命令只操作已有控制数据库，目录错误或缺少正确主密钥时会拒绝，不会新建一个“假重置”数据库。不要删除数据库、主密钥或执行 `docker compose down -v` 来找回管理员密码。该 CLI 为新增功能，旧镜像没有此命令时需先更新镜像并保留原持久卷。

## 设备切换

先停旧写入者，保存旧配置和脚本/注入库校验值。新服务不兼容旧的任意 shell 命令槽，不能让新旧主机同时控制音箱。

在已获批准的维护窗口将 [spk_agent_v2.sh](../device/spk_agent_v2.sh)、更新后的 [spk_net.sh](../device/spk_net.sh) 和 [spk_conf.sh](../device/spk_conf.sh) 配套部署到原设备目录，保留既有 [play601.sh](../device/play601.sh)。在设备自己的配置加入 `SPK_NET_PROTOCOL=v2`，把大脑目的地址改为 R76s；这些源文件不自动推送设备。

每个待替换文件先写到目标目录内的临时文件，核对校验值和 shell 语法，脚本补齐执行权限后再用同目录 `mv` 替换；不要直接覆盖正在运行的脚本。保留旧文件与权限，确认三份配套脚本齐全后才切换协议。只停止已核实身份的应用控制代理，不盲杀进程、不停止或重启原厂语音/网络服务，也不改 init、crontab 或注入库；不确定进程身份时停止部署。

通过可信维护通道把 control 的设备令牌写入设备 `/mnt/UDISK/spk/net.token`，权限 0600；不要把令牌写到源文件、命令历史、普通备份或截图。可以从可信终端导出，但不要把输出发回聊天：

```sh
docker compose exec -T control python -m spk_platform.cli export-device-token
```

v2 设备仅接受版本/ID/generation/TTL 验证后的固定动作及参数，调用固定播放脚本，不执行 `sh -c`。HTTP 失败不成为命令，已执行 ID 去重；重启/断电时仍可能存在不确定状态，不能承诺分布式绝对 exactly-once。旧 generation 的结果不能结束新播放。

播放状态区分：准备任务、命令接收、媒体 GET、播放器状态与实际可听声音。最后一项默认 unknown，HTTP 200 和 D-Bus `NoReply` 都不是“听到声音”的证明。自然完成依赖新的播放器状态变更；证据缺失时不猜进度或自动宣布完成。

队列规则：准备或设备播放失败会跳到下一首，失败的闹钟会恢复夜间静音；唤醒、语音回答、重播、上一首和单曲循环只替换当前曲目，保留后续队列。播放器在距曲目结尾 15 秒以上就回到停止或暂停态（实体键、手机投屏或原生唤醒）时按中断处理，不自动切下一首，避免抢占手机播放。设备空轮询由服务端最多挂起 3 秒（`SPK_DEVICE_HOLD`，0–4），命令一到即返回；设备代理会重试未送达的播放/完成回报，并上报原生控制中心造成的暂停（`0x4`）。

曲间衔接：音频末尾的 45 秒静音不能去掉——固件在“总长 − 15 秒”处发出切歌信号，原生控制中心随后会尝试连接云端、失败后暂停播放器，静音尾巴让这一下落在静音里。现在不再等到那一刻：设备报告开始播放后，服务端在“人声结束 + 曲间切换余量”（播放策略页，默认 1.5 秒）时直接切到下一首；队列为空时发送停止，结束静音尾巴。当前曲目开始播放后会预取下一首（随机播放时预取的就是下一首），已缓存的网易云曲目不再重新解析地址。听到结尾被截掉就调大余量。

唤醒续播：唤醒打断音乐时记录曲目和位置。第一轮在“唤醒后无人说话续播”秒数内（语音页，默认 8 秒，0 关闭）没识别到任何语音就结束会话，并从打断处前 3 秒继续播放（服务端从缓存文件截取剩余部分，曲目已接近结尾则继续队列）。说了话时，会在语音回答播完后才进入下一轮聆听，避免把自己的回答当成用户的话；会话结束后才恢复音乐。说“下一首”、“停止”、点播新歌、重播或上一首会放弃这次续播，闹钟和语音回答被打断后不续播。以上时序均需真机验收。

## 模型与存储

Compose 分离控制 SQLite、主密钥、媒体缓存、音乐账号以及每个服务的鉴权卷。media/MCP 不挂载家庭记忆、设备令牌或主密钥。所有运行容器非 root、read-only 根文件系统、`init: true`、CPU/RAM/PID 限额和日志轮转，不挂 Docker socket 或宿主声卡。

KWS 文件放在只读模型目录的 `kws/` 下，提供 `model.json`：

```json
{
  "tokens": "tokens.txt",
  "encoder": "encoder.int8.onnx",
  "decoder": "decoder.onnx",
  "joiner": "joiner.int8.onnx",
  "keywords_file": "keywords.txt"
}
```

文件必须是目录内的普通文件；仅文件存在不代表模型匹配，目标机预检必须加载。默认图标、中文字体、音箱示意 PNG 随镜像构建提供，页面不依赖外部 CDN。

MCP 网络与宿主出口限制仍需 R76s 运维验收。应用已对 TCP 连接的真实 DNS 地址、URL、重定向、结果上限和远程 schema 做限制，但 Compose bridge 本身不是宿主/内网隔离防火墙。批准内网 Endpoint 时逐项放行；不得在主路由上未经评估修改规则。本版不提供任意第三方 stdio 安装或通用浏览器/shell 工具。

## 备份和回滚

页面普通导出仅含结构化设置和闹钟，不含云 Key、密码、会话、设备令牌或音乐账号。普通导入只生成草稿，应用后才恢复闹钟；旧账号/家庭记忆迁移需明确指定来源，默认不读取个人 Claude/home 配置。

含加密密钥记录的数据库备份使用 SQLite backup API，不复制正在写入的主数据库文件。只有密钥字段使用 AES-GCM，设置、曲目和业务状态不是全库加密：

```sh
docker compose exec -T control python -m spk_platform.cli backup
```

输出路径位于控制数据卷。备份文件与主密钥卷分开加密保管；没有正确主密钥不能恢复云 Key。恢复完整快照前停止 control/voice 等写入者；在新卷中保留一致的数据库、密钥和账号快照，校验后启动，禁止让旧二进制读取不兼容 schema。

回滚到旧部署时：停止新写入者，恢复原设备地址、`SPK_NET_PROTOCOL=legacy`、配套脚本和旧配置，再启动旧主机。不要执行 `docker compose down -v`，它会删除持久卷。版本化镜像及配套配置保留到真机验收和稳定性观察完成。
